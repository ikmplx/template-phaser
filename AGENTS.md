# Правила работы с прототипом

Конечный пользователь — геймдизайнер без опыта программирования и терминала. Цель — быстро проверять игровые гипотезы, а не строить универсальный движок. Общайся по-русски, простым языком; не требуй от пользователя править код, выполнять команды или настраивать серверы и зависимости.

## Запуск и устройство

- Запуск на Windows — двойным щелчком по `Play.cmd`: он использует установленный Python 3 и запускает локальный сервер; после игры пользователь закрывает его окно. Сервер использует порт 8000. Если он занят, сервер сообщает об ошибке и не останавливает чужие процессы. Серверу не нужны сторонние библиотеки и интернет. Phaser 3 и ресурсы находятся в проекте. Не требуй Node.js, сборщиков или сетевых CDN для запуска игры.
- Прямой запуск через `file://` оказался ненадёжным при загрузке текстур. Python-окружение для инструментов разработки создавай в `.venv` проекта; оно не является требованием для запуска игры.
- Сохраняй понятное сообщение об ошибке запуска. Избегай лишних библиотек, сложной архитектуры и панелей, которые не нужны текущей гипотезе.
- Сохраняй исходные AI-изображения отдельно от подготовленных игровых текстур. Уменьшай изображения качественно и проверяй их вид в игре; не перезаписывай исходники без необходимости.

## Изменения и проверка

- Реализуй запрошенную механику, сохраняя работающий запуск; добавляй сброс, настройки или тестовые сценарии, когда они полезны. Не подменяй поведение игры декоративной демонстрацией.
- Сервер записывает порт 8000 в `.server-port` в корне проекта. Перед использованием проверь, что сервер отвечает и отдаёт нужный проект: после аварийного завершения файл может устареть, а порт может занять другой процесс.
- По возможности проверяй игру в браузере через локальный сервер, включая ресурсы, ошибки JavaScript, действия пользователя, сброс и реальные правила механики. Для проверки можешь использовать адрес, предоставленный пользователем, или сам запустить временный сервер на свободном порту, если позволяют инструменты и права. По завершении останавливай только сервер, запущенный тобой; не останавливай сервер пользователя без его просьбы.
- Проверяй изменения `Play.cmd` и `server.py` отдельно: запуск игры и браузера, сообщение при отсутствии Python, понятное сообщение, если порт 8000 занят и остановку сервера. Проверка игры через `localhost` сама по себе не подтверждает работу двойного щелчка по `Play.cmd`.
- Успешное открытие страницы не доказывает корректность механики. Если автоматизация браузера или отдельная проверка недоступна, выполни доступные проверки и прямо сообщи об ограничении; не утверждай, что проверил то, чего не проверял.
- Инструменты проверки используй только если они доступны агенту; не превращай Node.js, Playwright или иные инструменты разработки в обязательные условия запуска игры пользователем.
- Учитывай уже сделанные изменения пользователя. Не выполняй разрушительные Git-операции без разрешения и не добавляй `.venv` в репозиторий. Создавай коммиты по просьбе пользователя; перед возвратом к предыдущей версии проверяй наличие несохранённых изменений и при необходимости выясняй, как с ними поступить.
- Правила конкретной игры описывай в её коде и пользовательской инструкции; не закрепляй их в общих правилах, чтобы проект можно было использовать для других прототипов.
- В ответе кратко объясняй, что изменилось, как открыть или обновить игру, что проверено и что осталось проверить вручную. Указывай существенные ограничения понятными словами.
